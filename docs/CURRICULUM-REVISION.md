## 2. 성취기준 층 — 자동 반영 또는 수동 확인 필요

### 기준 자료(지금 시행 판)와 고친 판
- `curriculum/standards/v<별책>.json` — 기준 고시의 별책 원문(교육부 > 입법·행정예고 > "[교육부 고시 제2022-33호] … 총론 및 각론 고시"의 첨부 hwp)에서
  규칙으로 뽑은 성취기준(코드 → 문장·과목·영역·학년군). 이 사이트가 다루는 별책 7권, 2,000개. 출처 주소·sha256 을 함께 적는다.
  지도(`curriculum/*.json`)의 성취기준 코드 1,553개가 모두 여기 있는지 시험이 확인한다. **자동 반영이 이 파일을 덮어쓰는 일은 없다.**
- `curriculum/standards/versions/v<별책>/<고시 id>.json` — 확인된 고친 판(고시 순서의 사슬). 고시일(`noticeDate`)·발견일(`discovered`)·
  검증일(`verified`)·학년별 시행일(`effective`)·앞 판(`prev`: 파일·sha256)·내용 해시(`contentSha256`)·출처를 함께 둔다.
- 상태: **scheduled**(시행 전 학년이 남음) → 매주 확인이 마지막 시행일이 지나면 **active** 로만 바꾼다(다시 받지 않음).
  어느 쪽이든 학생에게는 **그 학년의 시행 학년도(3월 1일)가 되었을 때만** 적용된다 — 기기 안에서 학생 학년·기기 날짜로 계산(`js/impact.js`).
  부칙의 학년별 순차 시행(예: 2025 초1~4·중1·고1 → 2026 초5·6·중2·고2 → 2027 중3·고3)을 학생마다 그대로 따른다.
```
node scripts/curriculum-standards.js --baseline     # 교육부 공식 첨부에서 다시 만들기
node scripts/curriculum-standards.js --check        # 형식·출처·판 해시 사슬·기록과 파일 일치·지도 코드 확인
```

### 읽는 규칙 (`scripts/lib/standards.js`, AI 없음)
- 코드 문법: `[학년군 + 과목 약어 + 영역 2자리 - 순번 2자리]` — `[2수01-01]` `[9사(지리)01-01]` `[10공수1-01-01]` `[12대수01-01]` `[12미적Ⅱ-01-01]` (원문 오타 꼴 `[4사01–01]`·`[12동역-01-01]` 도 표준 꼴로).
- 구조: "나. 성취기준" → `[초등학교 1∼2학년]` → `(1) 영역` → 코드로 시작하는 문장(정의) → `(가) 성취기준 해설`(코드로 시작해도 정의가 아님) → `(나) 고려 사항` → 다음 영역.
  과목은 앞 "차 례"의 순서와 "1. 성격 및 목표"의 순서로, 두 과목을 한 장에 담은 곳은 `[공통수학2]`·`<통합과학2>`·`[한국사 1]` 머리로.
- 문서 형식: hwp(복합 문서 직접 읽기) · hwpx · pdf(pdftotext, 줄바꿈 잇기·쪽 머리말 빼기) · xlsx(코드 칸 + 문장 칸) · zip(안의 문서들, CP949 이름).
- 실제 원문 검증: 별책 7권 모두 확인 문제 0건. 같은 국어과 별책을 hwp 와 pdf 로 각각 읽어 257개 모두 같았다.
- 확실하지 않으면 `issues` 로 남긴다: 줄 첫머리 코드 중 정의를 못 찾은 것, 같은 코드가 다른 문장으로 두 번, 학년군·영역 번호 어긋남, "다."로 끝나지 않는 문장, 차례와 본문의 과목 수 어긋남 등.

### 원문 찾는 공식 경로 (`scripts/lib/sources.js`)
1. 국가교육위원회 법령자료 — 고시를 찾은 그 글의 첨부
2. 국가법령정보센터 — 그 고시 판의 첨부
3. 교육부 입법·행정예고 — 교육부 고시일 때 고시 번호로 검색

비공식 블로그·자료 공유 사이트는 쓰지 않는다. **국가교육과정정보센터(ncic)는 robots.txt 로 자동 접근을 막아** 자동으로는 보지 않는다.
행정예고본·신구대비표·의견 검토 결과처럼 **확정 전 문서는 받지도 쓰지도 않는다.**

### 자동 반영 조건 (하나라도 불확실하면 수동 확인 필요 — `scripts/lib/revision.js` assess)
변경 비율만 보지 않는다. 출처·읽기·코드·학년 매핑·시행일·차례·중복을 모두 본다.
- **출처** 1) 공식 기관(https: ne.go.kr · moe.go.kr · law.go.kr) 주소에서 받은 파일 2) 확정 전 문서(행정예고·예고본·(안)·시안·신구대비·의견 검토·공청회·공표문)가 아님
  3) 문서 머리의 고시 번호·별책 번호가 이 고시·이 별책과 같음
- **읽기** 4) 문서 구조를 남김없이 읽음(`issues` 없음 — 줄 첫머리 코드는 모두 정의가 있음, 문장 끝, 차례와 본문의 과목 수) 5) 과목 목록이 앞 판과 같음(빠지거나 새로 생긴 과목 없음)
- **코드** 6) 앞 판에 없던 코드 앞부분(새 과목 약어)이 없음 7) 같은 코드의 과목·영역·학년군이 앞 판과 같음 8) 다른 별책의 코드와 겹치지 않음
  9) 같은 코드인데 문장이 크게 달라진 것(닮은 정도 < 0.35)이 없음 10) 바뀐 양이 전면 개편 수준이 아님(삭제 ≤ 20%, 변경 ≤ 30%, 추가 ≤ 50%)
- **학년 매핑** 11) 바뀐 코드의 학년군이 그 코드를 쓰는 이 사이트 과정의 학년과 맞음 — 다른 학년 과정에 붙지 않는다(변화마다 닿는 학년 `grades` = 학년군 ∩ 과정 학년을 적는다)
- **시행일** 12) 바뀌는 과정의 모든 학년에 부칙의 시행일이 있음 13) 두 공식 경로(국가교육위원회·국가법령정보센터)의 시행일·별책이 같다고 확인됨(아직 한쪽에 없거나 못 읽으면 기다린다)
- **차례·중복** 14) 앞선 고시의 같은 별책이 수동 확인으로 남아 있지 않고, 뒤 고시가 먼저 기록돼 있지 않음
  15) 같은 고시·별책은 한 번만 — 같은 원문(파일 해시) 또는 같은 내용(성취기준 해시)이면 그대로(멱등), 다른 원문이면 겹쳐 쓰지 않고 수동 확인

### 기록 · 보관 · 해시 · 되돌리기
- 기록 전: 비교한 앞 판을 `curriculum/history/standards/<시각>-<고시>-v<별책>/` 에 보관하고 manifest 에 파일별 sha256(기록 전·후)과
  자료 전체 해시(`curriculum/standards/` 전체, 기록 직전·직후)를 남긴다. 기록 → `curriculum/history/standards-log.json`.
- `curriculum/notices.json` 의 고시마다 고시일(`date`)·발견일(`discovered`)·시행일(`effective`)과 `analysis.volumes[별책]` =
  `scheduled`/`active`(새 판: 파일·해시·바뀐 문장·닿는 학년) · `unchanged` · `manual`(까닭) — 카탈로그·화면이 이것을 쓴다.
- 되돌리기는 먼저 파일 해시가 **기록 직후 그대로인지** 확인하고(그 뒤 사람이 고쳤으면 하지 않음), 판을 지운 뒤 **기록 직전 해시로 돌아왔는지** 다시 확인한다.
```
node scripts/curriculum-standards.js --history                 # 기록·되돌리기 기록(해시 포함)
node scripts/curriculum-standards.js --rollback [보관본 이름]    # 마지막(또는 지정한) 기록을 되돌림 → 그 별책은 수동 확인 필요(되돌림)
node scripts/curriculum-standards.js --retry nec-2026-1         # 수동 확인(되돌림 포함) 별책을 다음 확인 때 다시 판정(확인된 판은 그대로)
```
되돌린 별책은 `--retry` 전까지 다시 자동 기록하지 않는다. 같은 별책을 두 번 바꿨으면 최근 것부터 되돌린다.

### 수동 확인 복구 — 관리자는 공식 원문 파일만 지정 (`.github/workflows/curriculum-recover.yml`)
사이트는 그 과목에 **"교육과정 변경 감지 - 수동 확인 필요"** 를 보이고 기존 자료로 계속 가르친다. 관리자가 할 일은 원문 지정 하나뿐이다.
1. 공식 자료실(국가교육과정정보센터 > 교육과정 자료실 등)에서 그 별책의 **확정 원문**을 받는다.
2. `curriculum/incoming/<고시 id>/` 에 올리고 같은 폴더 `source.txt` 에 받은 곳 https 주소를 적는다(GitHub 웹에서 올려도 된다) —
   또는 Actions 에서 "교육과정 수동 확인 복구"를 직접 실행(고시 id·별책·파일 경로·받은 곳 주소, dry_run 이면 판정만).
3. 작업이 이어서 한다: 파싱 → 앞 판과 비교 → 검증(위 조건 2~15, 사람이 받은 파일은 국가교육과정정보센터 주소도 출처로 인정) →
   새 판 기록(scheduled/active) → 수동 확인 해제 → 카탈로그·`--check`·전체 테스트 → 통과하면 커밋·배포 → 관련 이슈에 결과 댓글·닫기.
   처리를 마친 원문은 `incoming/` 에서 지운다(출처·sha256 은 판 기록과 Git 이력에 남음).
   조건을 통과하지 못하면 아무것도 바꾸지 않고 이슈에 까닭만 남긴다(같은 댓글은 한 번만). 같은 원문을 다시 넣어도 바뀌는 것이 없다.
```
node scripts/curriculum-standards.js recover 받은파일 --notice nec-2026-1 --volume 15 --url 받은곳주소            # 판정만(로컬)
node scripts/curriculum-standards.js recover 받은파일 --notice nec-2026-1 --volume 15 --url 받은곳주소 --apply    # 통과하면 기록
```
(전면 개편 수준이면 3층 "다시 쓰기"로.)

### 화면 (학생 기기 안에서만 계산 — `js/impact.js`)
- 과정 화면: 확인된 판(✅ 바뀐 성취기준 목록, 바뀌기 전 문장, 관련 단원) · 수동 확인 필요 · 성취기준 그대로 · 지금 학년은 시행 전에 마치면 "바뀌기 전 교육과정으로 배워요".
- 단원: 이 학생이 **지금** 바뀐 성취기준으로 배우는 단원에만 "개정 반영 중", 단원 머리에 바뀐 문장(시행 전이면 "○○년 3월부터").
  변화마다 닿는 학년(`grades`)만 본다 — 묶음 과정(중1~3 등)의 다른 학년 변화가 지금 학년에 붙지 않는다.
- 설정 "교육과정 변경과 우리 학생": 이 기기의 학생마다 **지금 학년과 앞으로 다닐 학년**(학년도는 3월 1일 시작)에 실제로 닿는 변경만.
  학생 이름·학년·기록은 기기 밖으로 나가지 않는다(공개 교육과정 정보만 내려받아 기기 안에서 견준다).

두 고시 모두 국가교육위원회와 국가법령정보센터의 시행일·별책이 서로 같다(crossCheck same).

## 3. 다시 쓰기 층 (단원 설명·문제를 고쳐야 할 때)

| 단계 | 무엇이 | 자동? | 도구 |
|---|---|---|---|
| 1. 새 지도 | 바뀐 성취기준·단원 차례를 `curriculum/revisions/<판>/` 에 지금 지도와 같은 꼴로 | ✋ 사람(또는 지도 작성 워크플로) | — |
| 2. 비교 | 새로 쓸·다시 쓸·살펴볼·뺄 단원, 작업 목록 | ✅ | `scripts/curriculum-diff.js` |
| 3. 적용 | 지도 교체(옛 지도 → `curriculum/history/<판>/`), 없어진 단원 보관, 카탈로그·색인 | ✅ | `scripts/curriculum-apply.js` |
| 4. 표시 | 새 단원 "준비 중", 성취기준이 바뀐 단원 "개정 반영 중" | ✅ | `scripts/build-catalog.js` |
| 5. 다시 쓰기 | 작업 목록대로 새로 쓰기·고쳐 쓰기·독립 검토 | ✋ 워크플로 | `tools/content-workflow.js` |

```
node scripts/curriculum-diff.js curriculum/revisions/<판> --md docs/revisions/<판>.md --jobs tmp/revision-<판>.json
node scripts/curriculum-apply.js curriculum/revisions/<판> --dry-run
node scripts/curriculum-apply.js curriculum/revisions/<판>
```
단원 id 는 그대로 쓸 수 있으면 그대로(학생 기록·오답노트가 단원 id 로 기억한다). 마무리는 build-catalog·build-index → validate-content 오류 0 → `npx playwright test` 전부 통과 → 경로를 적어 커밋.

## 규칙
- 확실하지 않으면 반영하지 않는다(위 조건). 기존 자료는 지우지 않고 보관한다. 모든 반영은 기록되고 되돌릴 수 있다.
- 외부 생성형 AI·유료 서비스를 쓰지 않는다. 비밀(secrets) 없이 Actions 기본 토큰만 쓴다.
- 확인 도구는 저장소 관리 도구다. 사이트(페이지)와 학생 기기는 여전히 외부에 아무 요청도 보내지 않는다(AGENTS.md 규칙 4).
  robots.txt(RFC 9309)를 지키고, 자기 이름을 밝힌 UA 로 곳마다 한 주에 몇 번만 읽는다.
- 저장소에는 공개 교육과정 정보(고시·성취기준)만 둔다. 학생 이름·학년·학습 기록은 저장소·이슈·커밋에 들어가지 않는다.
- 읽지 못하면 실행이 실패로 끝나 저장소 주인에게 알림이 간다. 모든 경로가 막히면 이슈로 알린다.
