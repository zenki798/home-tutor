> 사용자 결정(2026-10-05): **AI 없이, 별도 자원 없이, 사람 손 없이** 개정을 반영한다.
> 원칙: **자동화 범위를 넓히는 것보다 잘못된 교육과정을 학생에게 주지 않는 것이 더 중요하다.** 확실하지 않으면 추측하지 않고

> 세 층으로 나눈다.

>    판정 조건을 모두 통과할 때만 기준 자료(`curriculum/standards/`)에 반영한다(백업·기록·되돌리기). 아니면 수동 확인 필요.
> 3. **다시 쓰기 층(선택)** — 바뀐 성취기준에 맞춰 단원 설명·문제를 고쳐 쓸 때(전면 개정 등).

## 2. 성취기준 층 — 자동 반영 또는 수동 확인 필요

### 기준 자료
`curriculum/standards/v<별책>.json` — 기준 고시의 별책 원문(교육부 > 입법·행정예고 > "[교육부 고시 제2022-33호] … 총론 및 각론 고시"의 첨부 hwp)에서
규칙으로 뽑은 성취기준(코드 → 문장·과목·영역·학년군). 이 사이트가 다루는 별책 7권, 2,000개. 출처 주소·sha256 을 함께 적는다.
지도(`curriculum/*.json`)의 성취기준 코드 1,553개가 모두 여기 있는지 시험이 확인한다.
```
node scripts/curriculum-standards.js --baseline     # 교육부 공식 첨부에서 다시 만들기
node scripts/curriculum-standards.js --check        # 형식·출처·지도 코드 확인
```

### 읽는 규칙 (`scripts/lib/standards.js`, AI 없음)
- 코드 문법: `[학년군 + 과목 약어 + 영역 2자리 - 순번 2자리]` — `[2수01-01]` `[9사(지리)01-01]` `[10공수1-01-01]` `[12대수01-01]` `[12미적Ⅱ-01-01]` (원문 오타 꼴 `[4사01–01]`·`[12동역-01-01]` 도 표준 꼴로).
- 구조: "나. 성취기준" → `[초등학교 1∼2학년]` → `(1) 영역` → 코드로 시작하는 문장(정의) → `(가) 성취기준 해설`(코드로 시작해도 정의가 아님) → `(나) 고려 사항` → 다음 영역.
  과목은 앞 "차 례"의 순서와 "1. 성격 및 목표"의 순서로, 두 과목을 한 장에 담은 곳은 `[공통수학2]`·`<통합과학2>`·`[한국사 1]` 머리로.
- 문서 형식: hwp(복합 문서 직접 읽기) · hwpx · pdf(pdftotext, 줄바꿈 잇기·쪽 머리말 빼기) · xlsx(코드 칸 + 문장 칸) · zip(안의 문서들, CP949 이름).
- 실제 원문 검증: 별책 7권 모두 확인 문제 0건. 같은 국어과 별책을 hwp 와 pdf 로 각각 읽어 257개 모두 같았다.
- 확실하지 않으면 `issues` 로 남긴다: 줄 첫머리 코드 중 정의를 못 찾은 것, 같은 코드가 다른 문장으로 두 번, 학년군·영역 번호 어긋남, "다."로 끝나지 않는 문장, 차례와 본문의 과목 수 어긋남 등.

### 원문 찾는 공식 경로 (`scripts/lib/sources.js`)
1. 국가교육위원회 법령자료 — 고시를 찾은 그 글의 첨부
2. 국가법령정보센터 — 그 고시 판의 첨부
3. 교육부 입법·행정예고 — 교육부 고시일 때 고시 번호로 검색

비공식 블로그·자료 공유 사이트는 쓰지 않는다. **국가교육과정정보센터(ncic)는 robots.txt 로 자동 접근을 막아** 자동으로는 보지 않는다.
행정예고본·신구대비표·의견 검토 결과처럼 **확정 전 문서는 받지도 쓰지도 않는다.**

### 자동 반영 조건 (하나라도 어기면 수동 확인 필요 — `scripts/lib/revision.js` assess)
1. 공식 기관(https: ne.go.kr · moe.go.kr · law.go.kr) 주소에서 받은 파일
2. 확정 전 문서(행정예고·예고본·(안)·시안·신구대비·의견 검토·공청회·공표문)가 아님
3. 문서 머리의 고시 번호·별책 번호가 이 고시·이 별책과 같음
4. 문서 구조를 남김없이 읽음(`issues` 없음)
5. 앞선 고시의 같은 별책 변경이 확인되지 않은 채 남아 있지 않음(차례대로만)
6. 바뀐 양이 전면 개편 수준이 아님: 삭제 ≤ 20%, 변경 ≤ 30%, 추가 ≤ 50% (기준 20개 이상일 때)
7. 같은 코드인데 문장이 크게 달라진 것(닮은 정도 < 0.35 — 뜻이 바뀌었을 수 있음)이 없음
8. 다른 별책의 코드와 겹치지 않음 · 9. 모든 성취기준의 과목을 앎 · 10. 고시의 학년별 시행일을 읽었음 · 11. 두 공식 경로의 고시 내용이 같음

### 반영 · 백업 · 기록 · 되돌리기
- 반영 전 파일 → `curriculum/history/standards/<시각>-<고시>-v<별책>/`(보관본 + manifest), 기록 → `curriculum/history/standards-log.json`
  (고시 번호·적용일·출처 주소·파일·sha256·추가/삭제/변경 수).
- `curriculum/notices.json` 의 고시마다 `analysis.volumes[별책]` = `applied`(바뀐 문장 목록 포함) · `unchanged` · `manual`(까닭) — 카탈로그·화면이 이것을 쓴다.
```
node scripts/curriculum-standards.js --history                 # 반영·되돌리기 기록
node scripts/curriculum-standards.js --rollback [보관본 이름]    # 마지막(또는 지정한) 반영을 되돌림 → 그 별책은 수동 확인 필요(되돌림)
node scripts/curriculum-standards.js --retry nec-2026-1         # 되돌린·수동 확인 고시를 다음 확인 때 다시 판정
```
되돌린 별책은 `--retry` 전까지 다시 자동 반영하지 않는다. 같은 별책을 두 번 바꿨으면 최근 것부터 되돌린다.

### 수동 확인 필요가 나오면 (이슈 "[수동 확인 nec-… 별책 N]")
사이트는 그 과목에 **"교육과정 변경 감지 - 수동 확인 필요"** 를 보이고 기존 자료로 계속 가르친다. 사람이 할 일은 한 가지:
공식 자료실(국가교육과정정보센터 > 교육과정 자료실 등)에서 그 별책의 **확정 원문**을 받아 같은 규칙에 넣는다.
```
node scripts/curriculum-standards.js analyze 받은파일 --notice nec-2026-1 --volume 15 --url 받은곳주소          # 판정만
node scripts/curriculum-standards.js analyze 받은파일 --notice nec-2026-1 --volume 15 --url 받은곳주소 --apply  # 통과하면 반영
```
사람이 받은 파일은 국가교육과정정보센터 주소도 출처로 인정한다. 조건(2~11)은 자동 반영과 같다. 통과하지 못하면 까닭이 나오고 아무것도 바뀌지 않는다
(예: 전면 개편 수준이면 3층 "다시 쓰기"로).

## 규칙
- 확실하지 않으면 반영하지 않는다(위 조건). 기존 자료는 지우지 않고 보관한다. 모든 반영은 기록되고 되돌릴 수 있다.
- 외부 생성형 AI·유료 서비스를 쓰지 않는다. 비밀(secrets) 없이 Actions 기본 토큰만 쓴다.
- 확인 도구는 저장소 관리 도구다. 사이트(페이지)와 학생 기기는 여전히 외부에 아무 요청도 보내지 않는다(AGENTS.md 규칙 4).
  robots.txt(RFC 9309)를 지키고, 자기 이름을 밝힌 UA 로 곳마다 한 주에 몇 번만 읽는다.
- 저장소에는 공개 교육과정 정보(고시·성취기준)만 둔다. 학생 이름·학년·학습 기록은 저장소·이슈·커밋에 들어가지 않는다.
- 읽지 못하면 실행이 실패로 끝나 저장소 주인에게 알림이 간다. 모든 경로가 막히면 이슈로 알린다.
