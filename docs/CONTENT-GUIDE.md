# 학습 내용 작성 안내 (CONTENT-GUIDE)

단원 파일(`data/units/<단원id>.js`)을 쓰는 사람(에이전트)을 위한 안내다.
형식의 정의는 `docs/ARCHITECTURE.md` §2.3(문제 생성 도구 R)·§3(서식 글)·§4(그림)·§7(데이터 형식)이 기준이고,
이 문서는 **어떻게 써야 좋은 단원이 되는가**와 **실제로 자주 틀리는 곳**을 적는다.

> 이 사이트를 쓰는 사람은 **혼자 공부하는 학생**이다. 옆에 물어볼 어른이 없다.
> 설명이 모호하면 그대로 오해하고, 정답이 틀리면 맞게 푼 아이가 "틀렸다"는 말을 듣는다.
> 그래서 **정확성 > 쉬움 > 분량** 순서로 중요하다.

---

## 1. 작업 순서

1. 읽는다: `AGENTS.md`(특히 규칙 3), `docs/ARCHITECTURE.md` §2.3·§3·§4·§7, 이 문서 전체.
2. 맡은 과정의 원본 지도(`curriculum/<묶음>.json` — 단원별 `topics`·`standards`)를 본다.
   **앞뒤 단원의 제목·topics 도 본다.** 앞 단원에서 배운 것은 써도 되고, 뒤 단원·다음 학년 내용은 정답 풀이에 쓰지 않는다.
3. **견본 단원 `data/units/math-e4-07.js` 를 먼저 읽는다** — 과목이 달라도 칸 쓰는 법(이해 확인 `check`, 오답 분석 `concept`·`why`·`wrong`, 생성기, 조사)의 기준이다.
4. 단원마다 `data/units/<단원id>.js` 를 쓴다 (§3 틀). 한 파일 = 한 단원.
5. 단원 하나를 쓸 때마다 검사한다:
   ```bash
   cd "/d/11. AI 작업실/작업10(가정교사)" && node scripts/lint-unit.js <단원id>
   ```
   형식·정답 자기 일관성·서식 글(백슬래시)·그림·생성기 300회·조사까지 본다. 오류는 모두 고친다.
   경고도 고치는 것이 원칙이고(특히 조사·why·concept), 남긴다면 이유를 보고에 적는다.
6. **모든 문제를 직접 다시 푼다.** `node scripts/print-unit.js --unit <단원id> --hide-answers --seeds 8` 로 정답을 가린 채 뽑아 풀고,
   `--hide-answers` 없이 다시 뽑아 비교한다. 정답 번호(`answer`)는 보기의 몇 번째인지 0부터 다시 센다.
7. 끝나면 보고: 쓴 단원, 단원별 문제 수·생성기 수, 검사 결과(오류·경고 수 그대로), 확신이 없는 내용.

**하지 않는 것:** 다른 과정·다른 사람의 파일 고치기, 엔진(`js/`)·검사기 고치기, `npx playwright test` 전체 실행(사용자 PC 가 무거워진다).
엔진이나 검사기에 문제가 있어 보이면 고치지 말고 보고에 적는다.

## 1.5 가정교사 흐름

화면은 단원을 이렇게 가르친다: **개념 설명 → 이해 확인 → 문제 풀이 → 오답 분석 → 추가 설명** (ARCHITECTURE §7.4).
그래서 단원에는 개념 카드마다 이해 확인 문제(`check`), 문제마다 관련 카드(`concept`)와 오답 진단(`why`·`wrong`)이 있어야 한다.
학생 수준(기초 다지기·보통·도전)에 따라 화면이 `easy` 설명을 먼저 보이거나 문제 난이도(level)를 고르므로,
`easy` 는 **기초 학생이 처음 읽는 설명**이라고 생각하고 쓴다(교과서 설명을 줄인 것이 아니라 다른 길: 비유·구체물·그림).

## 2. 말투와 눈높이

| 학교급 | 말투 | 눈높이 |
|---|---|---|
| 초1~2 | 쉬운 해요체 | 한 문장 25자 안팎. 한자어 대신 쉬운 말("합"보다 "모두 몇 개"). 수는 작게. 그림(`fig`)을 많이 |
| 초3~6 | 해요체 | 교과 용어는 처음 나올 때 풀어서 설명("**분모**: 전체를 똑같이 나눈 수") |
| 중학교 | 해요체 | 교과 용어를 쓰되 정의를 분명히. 왜 그런지 이유까지 |
| 고등학교 | 합니다체 | 정확한 용어, 간결한 설명, 증명·원리의 흐름 |
| 대학·성인 | 합니다체 | 간결·정확. 실생활·전공과의 연결 |

- 한 단원 안에서 말투를 섞지 않는다.
- 학생을 부를 때 "여러분" 정도로. 반말·과장된 감탄("대박!")·유행어·이모지 남발 금지(상자 첫머리 💡 ⚠️ 정도만).
- 예시 인물: 흔한 가상 이름(민수, 지아, 서준, 하윤, 도윤, 수아 …). 실존 인물·연예인·상표·상호를 예시로 쓰지 않는다(역사 인물·과학자는 학습 내용이면 괜찮다).
- 돈은 원 단위, 길이·무게는 미터법. 날짜·통계를 "올해", "최근" 처럼 시간이 지나면 틀리는 말로 쓰지 않는다(필요하면 연도 명시).

## 3. 단원 파일의 틀

```js
/* <과정 제목> · <단원 제목> */
Tutor.registerUnit({
  id: 'math-e4-05',
  course: 'math-e4',
  title: '분수의 덧셈과 뺄셈',          // 카탈로그의 단원 제목과 같게
  summary: '분모가 같은 분수끼리 더하고 빼는 방법을 배워요.',
  goals: ['…할 수 있어요.', '…'],      // 2~4개
  standards: ['[4수01-15]'],           // 교육과정 지도(job-context)의 성취기준을 그대로 — 다르면 lint 경고, 화면에 "개정 반영 중"(docs/CURRICULUM-REVISION.md)
  concepts: [ … ],   // 3~6
  examples: [ … ],   // 1~3
  terms: [ … ],      // 3~10
  practice: [ … ],   // 8~12 (level 1·2)
  advanced: [ … ],   // 3~6 (level 3)
  deeper: [ … ],     // 1~2
  faq: [ … ],        // 2~4
  mistakes: [ … ],   // 1~3
  gens: [ … ],       // 수학 2개 이상 (과학 계산 단원도 권장)
  vocab: [ … ],      // 영어 단원 8~20
});
```

### 3.1 개념 카드 `concepts` — "이론"

카드 한 장 = **생각 하나**. 순서대로 읽으면 단원이 이해되게 쌓는다.

- 구성: **무엇인가(정의)** → **왜 그런가(직관·이유)** → **예 하나** → (팁·주의 상자).
- 길이: 초등 3~6문장, 중등 4~8문장, 고등 이상 5~10문장 + 수식. 한 카드가 화면 두 개를 넘지 않게.
- `easy`: 어려운 카드에는 **다른 방식의** 쉬운 설명(비유·그림·구체물)을 넣는다. 같은 말을 줄인 것이 아니라 다른 길로 설명한다.
- `fig`: 그림이 이해를 돕는 곳에(분수 모형, 수직선, 좌표평면, 도형, 그래프, 시계 …).
- 핵심 용어는 `**굵게**`. 비교는 표. 팁은 `> 💡 …`, 주의는 `> ⚠️ …`.
- `check` (**이해 확인 문제, 카드마다 1개**): 카드를 막 읽은 학생이 "알아들었는지" 확인하는 쉬운 문제. 카드 내용 그대로를 묻는다(다른 카드·응용 금지).
  choice(보기 3개)나 ox 가 좋다. `explain` 은 카드의 핵심을 한 번 더 짚는 말로. choice 면 `why` 도 넣는다.
  ```js
  check: { type: 'ox', q: '$\\frac{2}{5}+\\frac{1}{5}$을 계산할 때 분모끼리도 더해요.', answer: false,
           explain: '분모는 조각의 크기라서 그대로 두고, 분자끼리만 더해요. $\\frac{3}{5}$예요.' }
  ```

### 3.2 예제 `examples` — 풀이를 보여 주기

- `q`: 그 단원의 대표 문제. `steps`: 한 단계 = 한 동작 + 이유("분모가 같으니 분자끼리 더해요: $3+6=9$"). 2~6단계.
- `answer`: 최종 답(서식 글).

### 3.3 용어 `terms`

`{ term: '진분수', def: '분자가 분모보다 작은 분수예요. 예: $\\frac{2}{5}$' }` — 질문 답변의 "○○이 뭐예요?"에 그대로 쓰인다.
뜻은 학생 말로 한두 문장 + 예.

### 3.4 문제 `practice` · `advanced`

| level | 이름 | 기준 |
|---|---|---|
| 1 | 기본 | 개념 카드 하나를 그대로 적용. 한 단계 |
| 2 | 실력 | 두 단계 이상, 문장제, 앞 단원과 섞기 |
| 3 | 심화 | 거꾸로 생각하기·조건 맞추기·여러 개념 연결. **그 학년 범위 안에서** 깊게(선행 개념이 필요하면 안 된다) |

- `practice` 8~12개(level 1 이 절반 이상), `advanced` 3~6개(level 3).
- 유형을 섞는다. 한 단원이 전부 choice 이거나 전부 short 이지 않게.
- `explain`(해설)은 **가르친다**: 정답만이 아니라 왜 그런지, 계산 과정. 오답 보기가 왜 틀렸는지도 한마디.
- `hint`: level 2·3 에는 되도록. 답을 알려 주지 말고 첫걸음만.
- **오답 분석** — 이 사이트는 정답만 알려 주는 것이 아니라 "왜 틀렸는지"를 짚어 주는 가정교사다.
  - `concept`: 이 문제가 연습하는 개념 카드 번호(0부터). 틀린 학생에게 그 카드를 다시 보여 준다(추가 설명). **모든 문제에 넣는다.**
  - `why` (choice): 보기마다 그 보기를 고른 학생이 무엇을 잘못 생각했는지 한 문장. 정답 칸은 `''`. 오답 보기를 실수에서 만들었다면 이유도 바로 쓸 수 있다.
    `why: ['', '분모끼리도 더했어요. 분모는 조각의 크기라서 그대로예요.', '분자를 하나 더 셌어요. 2+3을 다시 세어 보세요.', '빼기를 했어요. 문제는 더하기예요.']`
  - `wrong` (short): 자주 나오는 틀린 답과 진단. `[{ a: '3/10', why: '분모끼리도 더했어요.' }]` — a 는 그 문제의 채점 방식(check)으로 비교된다(number 면 값이 같으면 걸린다).
  - 진단은 학생을 탓하지 않는 말로: "~했어요. ~해 보세요."
- 부정 질문은 `**옳지 않은**` 처럼 굵게. 초등에는 이중 부정 금지.
- 문제는 혼자 읽어도 뜻이 통해야 한다. "위 그림", "앞 문제" 처럼 다른 문제를 가리키지 않는다(그림이 필요하면 그 문제의 `fig`).

### 3.5 심화 학습 `deeper`

교과서 밖으로 한 걸음: 원리의 증명(학년에 맞게), 생활 속 쓰임, 개념의 역사, **다음 학년과의 연결**("5학년에서는 분모가 다른 분수도 더해요").
문제를 내지 않고 읽을거리로 쓴다.

### 3.6 질문 `faq` · 실수 `mistakes`

- `faq`: 학생이 **실제로** 물을 법한 질문. "왜 분모끼리는 안 더해요?", "음수 곱하기 음수는 왜 양수예요?", "현재완료랑 과거는 뭐가 달라요?"
  답은 2~5문장. 질문 답변 검색이 이것을 찾아 보여 준다 — 질문 문장을 학생 말투로 쓴다.
- `mistakes`: 자주 하는 실수와 바로잡기. "분모끼리도 더해서 $\\frac{3}{10}$ 이라고 쓰는 실수 — 분모는 그대로 둬요."

## 4. 문제 유형과 채점 — 꼭 알아야 할 함정

채점은 `TutorMath.checkAnswer`(ARCHITECTURE §2.5)가 한다. 검사기가 "정답을 넣으면 정답으로 채점되는지"를 모든 문제에 대해 확인한다.

### 4.1 `choice` (보기 고르기)

```js
{ id: 'p3', level: 1, type: 'choice',
  q: '$\\frac{2}{7}+\\frac{3}{7}$의 값은 무엇일까요?',
  choices: ['$\\frac{5}{7}$', '$\\frac{5}{14}$', '$\\frac{6}{7}$', '$\\frac{1}{7}$'],
  answer: 0,
  explain: '분자끼리 더하면 $2+3=5$, 분모는 그대로 7이에요. 그래서 $\\frac{5}{7}$예요. $\\frac{5}{14}$는 분모끼리도 더한 실수예요.' }
```

- 보기 4개(초1~2는 3~4개, 최대 5개). 화면이 보기를 **섞는다** — `answer` 는 원래 배열의 번호(0부터).
- 오답은 **그럴듯한 실수**에서 만든다(분모끼리 더하기, 부호 실수, 비슷한 용어). 터무니없는 오답은 공부가 안 된다.
- **값이 같은 다른 표기를 오답에 넣지 않는다**: 정답 $\frac{1}{2}$ 에 오답 $\frac{2}{4}$ 가 섞이면 정답이 둘이다.
- "모두 고르시오"·"①, ② 모두"처럼 보기 순서에 의존하면 `fixed: true`(섞지 않음). 크기 순 보기도 `fixed: true` 가 자연스럽다.
- **형태**를 묻는 문제(대분수로 바르게 나타낸 것, 기약분수, 바른 맞춤법)는 choice 로 낸다. short 로는 형태를 확실히 채점할 수 없다(아래).

### 4.2 `short` (답 쓰기)

```js
{ id: 'p7', level: 2, type: 'short',
  q: '우유가 $\\frac{7}{10}$ L 있었어요. 지아가 $\\frac{4}{10}$ L를 마셨어요. 남은 우유는 몇 L일까요?',
  answer: '3/10', check: 'number', unit: 'L',
  hint: '처음 양에서 마신 양을 빼요.',
  explain: '$\\frac{7}{10}-\\frac{4}{10}=\\frac{3}{10}$이므로 $\\frac{3}{10}$ L가 남아요.' }
```

| check | 언제 | 정답 칸 | 주의 |
|---|---|---|---|
| `number` | 답이 **수**일 때 (정수·소수·분수·대분수) | `'3/10'`, `'1 2/5'`(대분수: 자연수 공백 분수), `'-4'`, `'2.5'` | **값**이 같으면 정답: `6/8`·`3/4`·`0.75` 모두 정답. 형태는 채점 못 한다 |
| `text` | 답이 **낱말·짧은 말**일 때 | `['광합성']`, `['이순신', '이순신 장군']`, `["isn't", 'is not']` | 비교할 때 공백·대소문자·끝 마침표를 무시한다 → **수에 쓰면 안 된다**(`1 3/6` 과 `13/6` 이 같아진다) |
| `expr` | 답이 **식**일 때 | `'2x+3'` | 값이 같은 식이면 정답(`3+2x` 도). **인수분해·전개처럼 형태가 목표면 choice 로** |
| `set` | 답이 **여러 수**일 때 | `['2', '3']` 또는 `'2, 3'` | 순서 무관. 학생은 "2, 3", "x=2 또는 x=3" 처럼 써도 된다 |

- 단위는 `unit` 칸에. 학생이 "12cm" 라고 써도 정답이 된다. 문제 글에도 무엇을 쓰는지 밝힌다("몇 cm일까요?").
  채점기는 단위를 붙여 쓴 꼴("80만원"), 여러 낱말 단위의 앞 낱말만 쓴 꼴("7번째"·"80만"), "25도"(°C·℃·°F), "퍼센트포인트"(%p)도 받는다.
  그래서 이런 꼴을 `wrong` 의 틀린 답으로 쓰면 검사기가 오류를 낸다. %와 %p 는 다른 단위로 본다.
  여러 값을 쓰는 `check: 'set'` 문제에도 `unit` 을 줄 수 있다 — 학생이 "38.9%, 45.1%"처럼 원소마다 단위를 붙여 써도 정답이 된다.
  "답은 80만 원입니다"·"약 12 cm"처럼 문장으로 쓴 수 답도 수만 보고 채점한다. 과학 표기("1.2×10⁻³", "3×10^8", "1.2e-3")도 값으로 읽는다(지수 ±15 까지).
  지수가 큰 값(6.02×10²³)은 unit 을 "× 10²³" 처럼 두고 앞수만 정답으로 — 학생이 "6.02×10^23" 이라고 써도 정답이 된다.
  우리말 큰 수("15만 원"·"1억 2천만")도 값으로 읽는다. unit 이 "원"이고 정답이 150000 이면 "15만 원"도 정답, unit 이 "만 원"이면 예전처럼 그 단위의 수(15). 수가 들어 있는데 읽을 수 없는 답은 화면이 채점하지 않고 다시 써 달라고 한다.
- `text` 정답은 **허용할 표기를 모두** 넣는다(띄어쓰기는 자동으로 무시된다): 줄임말, 한자/한글 표기, 'colour'/'color' 같은 철자.
  허용 표기가 너무 많아지면 choice 로 바꾼다. 문장을 쓰게 하는 문제는 내지 않는다(자동 채점 불가).
- 영어 `text` 정답: 대소문자·끝 마침표는 무시된다. 축약형(`don't` / `do not`)은 둘 다 넣는다.

### 4.3 `ox`

`answer: true`(O) 또는 `false`(X). 문장이 **분명히** 참이거나 거짓이어야 한다("대체로", "보통" 같은 말로 애매하게 만들지 않는다).
X 문제의 해설은 무엇이 틀렸고 바르게 고치면 어떻게 되는지까지.

### 4.4 `order` (순서 맞추기)

```js
{ id: 'p9', level: 2, type: 'order',
  q: '일어난 순서대로 놓으세요.',
  choices: ['고조선 건국', '삼국 통일', '고려 건국', '조선 건국'],
  answer: [0, 1, 2, 3],
  explain: '고조선(기원전 2333년, 전해 오는 이야기) → 신라의 삼국 통일(676년) → 고려 건국(918년) → 조선 건국(1392년).' }
```

- 항목 3~6개, **항목끼리 글자가 겹치면 안 된다**(영어 낱말 배열에 'the' 가 두 번이면 어느 'the' 인지 채점이 갈린다 → 'the boy' 처럼 묶는다).
- `answer` 는 올바른 순서대로 놓은 원래 번호. 화면이 항목을 섞어서 보여 준다.

### 4.5 그림이 있는 문제

`fig` 를 문제 객체에 넣는다(ARCHITECTURE §4). 예: 시계 읽기 `{ type: 'clock', h: 3, m: 30 }`, 수직선 `{ type: 'numberline', min: 0, max: 2, step: 0.1, labelEvery: 5, points: [{ x: 1.3, label: '?' }] }`.
그림에 정답이 보이면 안 된다(라벨에 답을 쓰지 않기).

## 5. 서식 글과 수식 — JS 문자열의 함정

### 5.1 백슬래시는 두 번

단원 파일은 JS 다. JS 문자열 안에서 `\` 는 특수 문자다. **TeX 명령의 백슬래시는 반드시 두 번 쓴다.**

| 쓴 것 | JS 가 만드는 글자 | 결과 |
|---|---|---|
| `'$\\frac{3}{4}$'` | `$\frac{3}{4}$` | ✅ 분수 |
| `'$\frac{3}{4}$'` | `$` + 폼피드 문자 + `rac{3}{4}$` | ❌ 깨짐 (`\f` 는 폼피드) |
| `'$3\times4$'` | 탭 + `imes` | ❌ (`\t` 는 탭) |
| `'$x\neq 0$'` | 줄바꿈 + `eq` | ❌ (`\n` 은 줄바꿈) |
| `'$\sqrt{2}$'` | `sqrt{2}` | ❌ 소리 없이 백슬래시가 사라짐 |

검사기가 이런 흔적(제어 문자, 백슬래시 빠진 명령 이름, 깨진 글자 �)을 오류로 잡는다. 그래도 처음부터 `\\` 로 쓴다.

띄어쓰기를 고르는 문제: 검사기는 보통 보기의 공백을 지우고 같은 보기인지 본다. 문제 글에 "띄어 쓰(쓴·씀…)"·"붙여 쓰(쓴…)"가 있으면 공백까지 견주므로 띄어쓰기만 다른 보기를 그대로 쓸 수 있다(2026-10-09). 띄어 쓴 자리를 `∨` 로 보이게 쓰는 것도 좋다(성인 맞춤법 05·06 처럼 — 문제 글에 "(∨ 표시는 띄어 쓴 자리)").
줄바꿈은 `\n`, 문단 나눔은 `\n\n`.

### 5.2 언제 `$…$` 를 쓰나

- 분수·거듭제곱·근호·문자(변수)·기호(×, ÷, ≤, π, ∠ …)가 있으면 `$…$`.
- 그냥 수와 단위는 수식 없이 써도 된다: "12 cm", "3,500원".
- 변수는 항상 수식 안에: "$x$의 값", "$a$와 $b$".
- **조사는 수식·수에 붙여 쓰고, 읽는 소리에 맞게 고른다.** $\frac{9}{8}$ 은 "8분의 구"로 읽으니 `$\\frac{9}{8}$는`, $\frac{6}{5}$ 는 "5분의 육"이니 `$\\frac{6}{5}$이`,
  $1\frac{2}{5}$ 는 "1과 5분의 이"이니 `$1\\frac{2}{5}$예요`. 받침 있는 소리: 1(일)·3(삼)·6(육)·7(칠)·8(팔)·0(영)과 10·100·1000…(십·백·천);
  받침 없는 소리: 2(이)·4(사)·5(오)·9(구). 'ㄹ' 받침(1·7·8)은 '으로'가 아니라 '로'(1로, 7로). 영어 낱말·단위는 읽는 소리로(m → 미터, L → 리터).
  - 생성기에서 수가 바뀌는 자리는 `R.josa(수, '이에요/예요')` 로 고른다(§6). 분수·대분수는 **분자**가, 식은 **마지막에 읽는 수**가 기준이다.
  - 가장 좋은 것은 조사가 필요 없게 쓰는 것: "계산해 보세요.\n\n$…$", "답: $…$".
- 한글을 수식 안에 넣을 때는 `\\text{넓이}` 또는 그냥 한글(곧은 글씨로 나온다).
- 대분수: `$2\\frac{1}{3}$`. 곱셈 기호: 초등은 `\\times`, 중등 이상 문자식은 생략·`\\cdot`. 나눗셈: 초·중 `\\div`.
- 달러 글자가 필요하면 `\\$`(드물다 — 돈은 원으로).

### 5.3 그 밖의 서식

`**굵게**`, `__밑줄__`(국어: "밑줄 친 부분"), `[[빈칸]]`(빈칸 상자, 안 글자는 보이지 않고 길이만), 목록(`- `, `1. `), 표(`| 가 | 나 |` + `|---|---|`), 상자(`> 💡 …`).
HTML 태그는 쓰지 않는다(글자 그대로 보인다).

## 6. 문제 생성기 `gens` (수학 필수)

같은 단원을 다시 공부해도 매번 새 문제가 나오게 한다. 예상문제의 절반 이상이 생성기에서 나온다.

```js
gens: [
  {
    id: 'add-same-den',          // 단원 안에서 고유
    level: 1,
    title: '분모가 같은 진분수의 덧셈',
    make: function (R) {
      var d = R.int(5, 12);
      var a = R.int(1, d - 2);
      var b = R.int(1, d - 1 - a);          // 합이 진분수가 되게
      var s = a + b;
      return {
        type: 'short', check: 'number',
        q: '계산해 보세요.\n\n$\\frac{' + a + '}{' + d + '}+\\frac{' + b + '}{' + d + '}$',
        answer: s + '/' + d,
        explain: '분모는 그대로 두고 분자끼리 더해요. 답은 $\\frac{' + s + '}{' + d + '}$' + R.josa(s, '이에요/예요') + '.',
      };
    },
  },
],
```

### 6.1 규칙

- **`R` 만 쓴다** (ARCHITECTURE §2.3). `Math.random`·`Date` 금지 — 같은 seed 는 같은 문제여야 한다(검사기가 확인).
- 숫자 범위는 **그 학년에 맞게**: 초1 은 20 이하, 초등은 음수 없음, 약분을 안 배운 학년(초3~4)은 답을 약분하지 않은 꼴로 보여 준다.
- 나쁜 경우를 피한다: 0으로 나누기, 답이 0인 뻔한 문제(의도한 게 아니면), 1을 곱하기, 분모가 1, 같은 수 두 번, 너무 큰 수.
- 생성기 하나 = 기술 하나. 단원 핵심 기술마다 하나씩, level 1 과 level 2 를 함께(가능하면 level 3 도).
- 300번 돌려 서로 다른 문제가 충분히 나와야 한다(검사기 경고: 20개 미만).
- `explain` 에 그 문제의 실제 수로 계산 과정을 쓴다.

### 6.2 자주 틀리는 곳

- **`Frac` 은 항상 기약분수가 된다.** `R.F(6, 8)` 은 `3/4`. 약분 전 모양(초4의 $1\frac{2}{4}$)을 보여 줘야 하면 문자열을 직접 만든다.
  `check: 'number'` 는 값으로 채점하므로 정답 칸은 `'6/8'` 이든 `'3/4'` 든 같다.
- **choice 오답 후보는 넉넉히(5개 이상) 준다.** `R.choices` 는 겹치는 오답과 정답과 같은 오답을 뺀다. 수가 특별한 경우(예: 두 실수 오답이 같은 값) 후보가 모자라면 throw → 검사기 오류.
  후보는 문자열로 비교되므로, **값이 같은 다른 표기**(`\\frac{2}{4}` 와 `\\frac{1}{2}`)가 정답과 오답으로 함께 나오지 않게 오답을 만든 뒤 값으로도 확인한다.
- 음수를 식에 넣을 때 괄호: `R.fmt.paren(-3)` → `(-3)`. 계수 1·-1 은 생략: `R.fmt.poly([1, -3, 2])` → `x^{2}-3x+2`.
- 소수 계산은 부동소수 오차가 난다(`0.1+0.2`). 정수로 계산하고 마지막에 `R.fmt.dec` 로 소수 표기, 또는 `Frac`.
- **조사**: 수가 바뀌는 자리 뒤의 조사는 `R.josa(수, '을/를')` 처럼 고른다(§5.2). 이름·물건을 `R.pick` 으로 바꿀 때도 `R.josa('민수', '이/가')`.
  `R.josa` 는 수(읽는 소리의 끝 — 일의 자리, 0으로 끝나면 십·백·천·만), 한글 낱말(마지막 글자의 받침), 영어 낱말·단위(대표 읽기)를 판단한다.
  쌍: `'은/는' '이/가' '을/를' '과/와' '으로/로' '이에요/예요' '이라고/라고' '이다/다'`.

### 6.3 과학·그 밖의 과목

과학 계산 단원(속력, 밀도, 용해도, 전류·전압·저항, 일과 에너지, 농도 …)은 생성기를 권장한다. 영어·국어·사회는 문제은행으로 충분하다(영어는 화면이 `vocab` 으로 낱말 문제를 자동으로 만든다).

## 7. 과목별 안내

### 국어
- 영역을 고르게: 듣기·말하기, 읽기, 쓰기, 문법, 문학, 매체.
- **문학 작품은 저작권이 끝난 것만 인용**한다: 1962년 이전에 세상을 떠난 작가(김소월, 윤동주, 한용운, 이상, 이육사, 김유정, 현진건, 이효석, 나도향, 방정환, 심훈, 정지용, 김영랑, 채만식 …)의 작품, 고전 문학(향가, 고려가요, 시조, 가사, 고전 소설, 설화).
  그 밖에는 **직접 쓴 글**(동시, 짧은 이야기, 설명문, 논설문)로 문제를 낸다. 현대 작가의 글·노래 가사·번역문은 인용하지 않는다. 확신이 없으면 직접 쓴다.
- 인용은 필요한 만큼 짧게(시 한두 연, 소설 몇 문장). 작가와 작품 이름을 밝힌다.
- 문법·맞춤법은 현행 규정(한글 맞춤법, 표준어 규정, 표준 발음법, 외래어 표기법)과 2022 개정 교육과정의 용어를 따른다. 예외가 많은 규칙은 "대부분"이라고 정확히 말한다.
- 쓰기·말하기 단원: 문장을 쓰게 하는 대신 "더 알맞은 문장 고르기", "고쳐 쓴 문장으로 바른 것", "빠진 내용 찾기" 꼴로.
- 초1~2 한글: 그림(`fig`)보다 글자 자체를 크게 다루는 문제(받침 고르기, 낱말 만들기 choice).

### 수학
- 생성기 2개 이상(핵심 기술마다). 문제은행에는 생성기로 만들기 어려운 개념·서술·문장제·그림 문제를 둔다.
- 도형·측정·그래프 단원은 `fig` 를 적극적으로(polygon, circle, angle, coord, bars, numberline …).
- 풀이에 그 학년에서 안 배운 방법을 쓰지 않는다(초등 문장제를 방정식으로 풀지 않기 — 거꾸로 생각하기, 그림).

### 영어
- `vocab` 8~20개: `{ w: 'library', m: '도서관', ex: 'I read books in the library.', exm: '나는 도서관에서 책을 읽어요.' }`. 그 학년 수준의 낱말. 예문은 직접 쓴다.
- 문법 설명은 한국어로, 예문은 영어(**굵게**로 초점). 수식(`$`)은 쓰지 않는다.
- 문제: 빈칸에 알맞은 말(choice), 낱말 쓰기(short text, 허용 표기 모두), 낱말 배열(order — 같은 낱말 두 번 금지), 짧은 글(3~6문장, 직접 씀) 읽고 답하기, 대화 완성.
- 초3~4 는 소리·낱말 위주(긴 문장 쓰기 금지). 발음은 한글로 적지 않는다(필요하면 "강세는 앞에" 정도).

### 사회·역사
- 사실·연도·용어는 교과서 수준에서 정확하게. 불확실하면 쓰지 않는다. 연도는 "○○년" 으로.
- 정치적으로 중립. 논쟁적 사안은 교육과정 서술을 넘지 않는다. 특정 정당·현직 정치인·종교를 평가하지 않는다.
- 역사: `order`(사건 순서), 원인·결과·의미를 묻는 choice. 인물은 업적과 시대를 함께.
- 통계·자료 해석은 `bars`·`line`·`pie` 그림 + 가상의 수치(실제 통계처럼 보이게 출처를 꾸미지 않는다. "가상의 자료" 라고 밝힌다).

### 과학
- 일상 예로 시작해 원리로. 오개념(무거운 것이 빨리 떨어진다, 겨울은 태양에서 멀어서 춥다 …)을 `mistakes`·`faq` 로 바로잡는다.
- 실험은 **집에서 안전하게 할 수 있는 것만** 권하고, 불·약품·전기는 "어른과 함께"를 분명히. 위험한 실험 방법을 자세히 쓰지 않는다.
- 단위는 SI(m, kg, s, N, J, W, A, V, Ω …). 수식은 `$…$`(예 `$v=\\dfrac{s}{t}$`).
- 성인 '생활 속 과학·건강'은 원리 이해 수준. 진단·처방·복용량 같은 의학 조언을 하지 않는다("증상이 있으면 의사·약사와 상담").

### 통합교과(초1~2)
- 아주 쉬운 말, 생활 습관·안전·계절·우리나라·이웃·자연 관찰. 문제는 choice(3개)·ox 위주, practice 8개 안팎.

### 대학·성인
- 대학: 국내 대학 1학년 교양·전공기초 수준. 정의·정리를 정확히, 계산 문제는 생성기.
- 성인: "다시 배우는" 사람을 존중하는 말투(아이 취급 금지). 실생활 예(가계, 직장, 뉴스). 법률·금융·건강은 상식·원리 수준이며 개인 상황은 전문가와 상담하라고 밝힌다.

## 8. 검증자(리뷰어) 점검표

내용을 검토하는 사람은 아래를 **하나도 빼지 않고** 본다. 문제를 찾으면 직접 고치고 무엇을 왜 고쳤는지 남긴다.

1. **정답**: 모든 문제(개념 카드의 `check` 포함)를 직접 푼다. choice 의 `answer` 번호, ox 의 참·거짓, short 의 정답 칸, order 의 순서. 해설의 계산.
   `why` 가 보기 순서와 맞는지(정답 칸이 ''), `wrong` 의 틀린 답이 정말 틀린 답인지(정답과 값이 같으면 안 된다), `concept` 번호가 맞는 카드인지.
2. **오답 보기**: 정답이 둘이 되는 보기(값이 같은 표기, 둘 다 맞는 진술)가 없는가. 오답이 그럴듯한가.
3. **사실**: 정의·연도·인물·과학 사실·문법 규정이 정확한가. 애매한 단정이 없는가.
4. **학년**: 그 학년 교육과정 안인가. 풀이에 안 배운 방법을 쓰지 않았는가. 말투·눈높이가 맞는가.
5. **생성기**: 코드를 읽고 경계 값(최소·최대)으로 머릿속에서 돌려 본다. 검사기로 seed 여러 개 출력을 뽑아 직접 풀어 본다:
   `node -e "require('./js/mathlib.js'); …"` 대신 `node scripts/validate-content.js --unit <id> --json` 이나 직접 vm 으로 실행해 문제 10개를 찍어 본다.
6. **채점 함정**: 수 답에 `text` 를 쓰지 않았는가, 형태를 묻는데 `number` 로 채점하지 않는가, 단위 칸, 허용 표기 누락.
7. **저작권·안전**: 인용한 작품이 저작권이 끝난 것인가, 교과서·문제집 문장을 베끼지 않았는가, 실존 인물·상표, 위험한 실험, 편향.
8. **서식**: 수식이 제대로 보이는지(백슬래시), 표·목록 모양.
9. 검사기 오류 0.
